# 程序与数据库完整性审查

范围：2026-09-09，澜序 SaaS 正式库 `za_spa_saas`（独立 PostgreSQL 5433）、服务端/Web 1.0.0、Windows 1.0.1。生产业务数据仅只读检查；业务写入回归使用 `za_spa_saas_test`，备份恢复使用临时数据库。

## 数据是否缺失

生产包含 84 张表、937 个字段、28 次迁移。迁移文件与生产记录无遗漏；生产和测试的表、字段、约束、索引、RLS 策略和触发器定义逐项一致。业务字段对照表 `business-schema-map.json` 中的字段没有缺失。574 个约束全部已验证，255 个外键，352 个索引均有效，11 个业务触发器无禁用项。

生产商家、门店、会员、订单、支付、库存等业务表目前均为 0 行；1 名平台管理员有效。该状态符合此前明确授权彻底删除商家的操作，不能将“表为空”认定为异常丢失。本次没有恢复已删除商家，也没有补造业务数据。平台登录会话、登录审计和迁移记录仍存在，这是系统自身管理记录。没有删除前的外部原始账本可供逐笔比较，因此不能证明历史上从未丢失过任何记录。

## 数据隔离与恢复

商家业务表启用强制 RLS。平台邀请和平台审计属于平台表，不采用业务 RLS；商家运行账号实际不能读取这些表及平台用户、平台会话。运行账号无超级用户、BYPASSRLS、建库、建角色、public schema CREATE 或整表 TRUNCATE 权限。现有平台会话无孤立用户引用。

5 份现存生产备份的文件 SHA-256 与清单一致；较早备份对应历史结构，不能当作当前全量备份。最新备份 `za_spa_saas-20260909T015039Z-5c696eba.dump` 在新建临时库完整恢复成功，84 张表的数据指纹与备份快照逐一一致，校验后删除临时库。加密恢复材料成功验证数据库连接、平台认证、JWT 及独立认证加密密钥；日志不输出密钥内容。
