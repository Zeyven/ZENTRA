# 采购与门店调拨验收

范围：新 SaaS 的采购、库存调拨工作流。旧项目与生产业务数据不在此次修改范围内。

## 已实现的业务

- 项目商品内新增「采购收货」「门店调拨」，沿用澜序的深绿、暖白界面与共用弹窗。
- 供应商选择、新增供应商、采购多行建单、分批收货、采购退货。尚未收货的单据可以填写原因取消；已收货的单据保留历史，走退货流程。
- 采购单显示订购量、累计收货和累计退货。收货上限为订购量减累计收货，退货上限为累计收货减累计退货；退货后补货另建采购单。
- 采购单价保存在原单据。库存报表继续按商品配置成本的流水快照统计，不声明已实现加权成本核算或供应商应付结算。
- 调拨明确选择目标店和对应商品，不按相同名称隐式匹配；两店单位必须一致。草稿不改库存，调出店确认发货时出库，调入店确认收货时入库；只允许取消未发货草稿。
- 采购和调拨列表使用每页 50 条的游标分页。单据明细由创建和处理响应直接返回，不为取得同一单据再发一次 GET。
- 表单失败保留输入；提交时防止连续点击；响应不明时锁定原表单并提供原请求编号重试。门店切换仍由会话 epoch 中止请求、销毁旧页面。
- 已有库存、采购或调拨记录的商品不能更改计量单位；门店编辑和商家模板下发执行相同规则。允许三位小数库存后的普通价格编辑。
- 新建商品初始库存默认为 0；编辑已有商品时库存字段只读，资产变化通过库存操作记录。

## 数据与授权

- 迁移 `015-inventory-workflows.sql` 增加采购版本和取消留痕，以及采购数量、采购/调拨状态约束。目前仅应用到独立测试数据库。
- 每次采购处理以读取的版本提交；订单锁、版本校验、库存流水和单据明细同事务提交。两个不同请求编号使用同一旧版本也只允许一次成功。
- 所有采购数据按会话商家、所选门店读取。调拨列表和详情同时校验两店访问权限；调拨操作同时校验两店 `items` 页面和 `adjust` 动作权限。
- 调拨重试在读取幂等保存结果前再次校验两店授权，撤销目标店权限后不能通过重放旧请求取得单据内容。
- 多行库存按商品编号加锁；缺货时整单回滚。建单与商品单位修改也通过商品锁串行化。
- 实时变化沿用现有单连接、按商家门店区分的事件机制。单据列表随事件刷新，正在编辑的采购明细保留原版本，服务端拒绝过期数量；用户刷新明细后再操作。

## 回归中发现并修正的问题

模板下发成功后原先等待整页列表刷新才释放共用提交锁。刷新稍慢时，用户立即新建另一种模板会打开表单，但保存点击被静默忽略。模板保存现在直接使用提交返回的记录更新列表，下发成功后立即结束该操作，列表刷新由现有实时机制负责。`tests/browser/templates.spec.ts` 在阻塞列表 GET 的情况下完成下一次优惠券模板保存，验证刷新不再阻塞操作。

并行运行两套验收时，支持权限测试原先选择「最后创建的平台管理员」，可能选到另一套测试账号。测试夹具现在返回本次真实登录的管理员 ID，并显式按该 ID 授权。生产支持权限校验没有放宽。完整后端首轮结果为 69/70，唯一失败由此夹具问题触发；修正后账号、门店权限和实时连接定向回归 17/17 通过。新增的采购调拨后端 8 项在完整回归中全部通过。

完整 Web/Electron 首轮结果为 10/11，模板流程暴露上述真实提交锁问题；修复后的采购、调拨、慢刷新模板定向浏览器回归 3/3 通过。所有这些测试均无跳过，不将首轮失败记录改写为一次性全部通过。

## 边界与后续验收

本轮不把供应商资料全面维护、采购应付结算、已发货调拨的异常物流处理或完整库存审计报表计为完成。全系统功能对照、生产部署、备份恢复、容量与安装共存验收仍需继续。正式库没有生成测试供应商、商品、采购或调拨记录。
