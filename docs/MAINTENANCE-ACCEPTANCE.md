# 门店维护日志

维护页面挂载于门店设置，仅老板及有效支持会话可读取当前选择门店。门店 ID 仍经过统一授权和强制 RLS；不存在空门店自动获得平台日志的规则。店长等经营角色不能访问诊断接口。

请求来源记录已通过商家授权的业务请求，包括校验失败；系统来源显示其中的 5xx。业务操作和敏感审计来自事务性审计，钟务来自真实钟务事件，同步来自真实持久事件。登录前失败、Nginx、主机日志、浏览器崩溃、设备驱动不在此采集范围，不用空白数据冒充已经接入。

诊断仅接受商家、门店、操作人、请求 UUID、HTTP 方法、路由模板、状态码及耗时，不记录查询参数、正文、密码、令牌或异常原文。详情对业务快照使用字段白名单。查询包含来源、日期、操作人、状态码、耗时、事件搜索与游标分页；单次导出最多 500 条并明确提示截断，导出本身留审计。

响应结束后进入最多 1000 项内存队列，每批每商家最多 50 请求，使用独立 RLS 事务，不沿用已经结束或其他商家的事务。队列满或写入失败有计数与时间反馈，不把日志写入失败说成业务失败。进程退出等待已排队写入；诊断队列并非资金审计替代品，进程强杀可能丢失尚未写入的诊断。

每商家诊断最多 10000 条、30 天；写入时修剪，后台每分钟最多检查 20 商家，包含停用商家。只清理诊断表，不删除经营流水、审计或同步事件。单商家恢复丢弃旧诊断和领券邀请，保留当前凭证的规则不变。

最初 3 项接口测试通过：真实请求与失败记录、跨店和跨商家拒绝、日志正文/查询隐私不出现、后台写入退出继承上下文、单商家数量及日期清理不改变另一商家和业务审计。停用商家定时清理、编译后服务运行及浏览器验收正在补验。
