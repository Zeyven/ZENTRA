# 桌面设备检测与辅助配置

入口：门店设置 → 设备接口 → 一键检测与配置。此修改尚未发布安装包或云端。

## 已实现

- Electron 主进程提供固定的只读检测接口，通过已有的可信主窗口校验。渲染进程不能提交命令、文件路径或扫描目标；不开放 Node 权限。
- 读取非回环的局域网 IPv4 网卡、子网掩码、当前 Windows PnP USB/键盘/串口信息和已知邻居缓存。不读取厂商注册表配置、登录凭证或业务日志。
- 设备结果只保留名称、类型、状态、COM 号、VID/PID，不返回完整设备实例 ID 或序列号。每类最多 256 条；PowerShell 超时 20 秒，隐藏执行窗口；并发调用复用同一次检测；后续手动检测重新枚举，不复用已完成的旧快照。
- 检查 18032、18034、18035 监听端口。实测 Windows 通配监听可以和某些地址专属监听同时成功，因此先逐个本机 IPv4 地址检查，再检查通配地址，避免将占用端口推荐为可用。检查完立即释放监听，不给设备发协议指令。
- 自动推荐可用端口；只有单网卡时预选地址，多网卡时由操作者选择。检测建议经按钮带入网关草稿，保留原授权生成、房间绑定和保存流程。
- 候选设备可填入刷牌器资料草稿；USB/串口候选还可填入报钟器资料草稿及 COM 地址。不会自动保存、安装驱动或把未知协议设为已知。
- 网页端、尚无检测桥的旧桌面端提示需要支持检测的 Windows 客户端。

## 实际验证

当前电脑检测到 3 个局域网 IPv4 地址、22 个候选设备，其中 5 个串口项；没有枚举错误。数字为检测时快照，不表示这些设备都是门店硬件。

TypeScript、服务端/Electron/Web 构建通过。单元验证包含不可信库存数据过滤、公共/无效地址过滤、端口占用与释放、桌面资源及网络隔离。真实 Electron 在隔离测试商家中完成设备检测、网卡选择、网关参数填入；浏览器回归覆盖配对文件、授权撤销和报钟器草稿。未进行安装升级测试。

## 尚未具备的能力

这不是“自动找到任何型号并直接营业”。邻居缓存可能陈旧或不完整，USB 接口不能证明设备用途；需要插拔对照、刷卡确认，以及房间/区域绑定。未实现主动全网扫描、自动安装驱动、网关自启动、未知厂商协议推断、点钟王业务写入或实体播报。端口检测属于快照，网关运行时仍须处理绑定失败。

参考：Microsoft [Get-NetNeighbor](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-netneighbor?view=windowsserver2025-ps) 定义其来源为邻居缓存；[Get-PnpDevice](https://learn.microsoft.com/en-us/powershell/module/pnpdevice/get-pnpdevice) 用于设备枚举。Electron [安全建议](https://www.electronjs.org/docs/latest/tutorial/security) 要求校验 IPC 发送方。


## 后续优化：插拔对照与过期建议

- 手动重新检测保留旧清单供对照，但检测中或检测失败时禁止用旧清单填参，并立即清除旧网关/报钟器建议。
- 新增、移除、状态或 COM 变化分别显示，可只查看新增或变化项。相同名称设备通过本次主进程内加盐 HMAC 匿名标识区分；实例路径只进入主进程计算，不传给网页、不记录、不上传。旧版本没有标识时按元数据及重复数量比较。
- 多网卡重复检测保留仍存在的选择；切换网卡清除原建议。局域网邻居只显示选中网卡同子网的候选项，排除自身、网络及广播地址，支持非 /24 掩码。
- 选择刷牌器资料后滚动并聚焦配置表单，仍需明确保存，不自动覆盖配置。
- 设备插拔差异算法通过构造样本测试；当前电脑连续真实检测与参数填入经 Electron 验证。未在实体店执行设备拔插或业务报钟验证。

## 一键保存所选配置

新增检测结果内的“选择用途，一键保存配置”：为刷牌器、报钟器分别选择候选设备后，一次提交，自动填写检测到的型号、连接方式和报钟器 COM 地址。已有配置必须核对变更后勾选允许更新。同一候选不能同时选作两类设备。

服务端 POST /api/merchant/v1/devices/configure 仅允许上述两类，复用原 settingsManage 权限、门店作用域、审计、版本检查；按固定顺序加锁，在一个事务中写入。使用幂等请求，整批冲突回滚，不留下部分更新。结果未知时保留原请求核对，并禁止重新检测丢失待确认请求。

验证：隔离数据库测试通过首次保存、幂等重试、重复类型拦截、第二项版本冲突导致第一项回滚、跨商家及门店隔离。真实 Electron 测试通过检测后选择两个候选一次保存、双击只提交一次、保存结果实际落库和覆盖确认。类型检查与服务端/Electron/Web构建通过。

本功能是“一键保存检测得到的配置”，不是“一键激活全部实体硬件”。点钟王仍走老板授权和房间绑定流程；报钟器及专用 USB/串口设备仍缺对应适配，保存状态保持 not_connected。不自动安装驱动，不猜测厂商协议。尚未发布云端或安装包。

## 客户端直接运行只读网关

新增桌面隔离桥 saas:gateway，固定 API 源，提供 start/stop/check/state。主进程校验独立 gw1 授权、当前云端授权房间、设备数量、设备 IP/编号与房间一致性后才监听指定的本机 LAN/回环地址。凭证仅保存在本次运行内存，不写入日志、状态结果或普通配置文件。

配对界面新增“在本机启动只读网关”，无需用户另装 Node.js 或手动执行命令；保留下载给独立测试网关的方式。一个客户端同时只运行一个门店网关，端口冲突时失败，不终止原厂进程。支持本机状态、停止和授权检查。每 15 秒检查心跳；授权撤销后云端查询立即拒绝，检测到 401/403 后关闭连接和监听。暂时断网不返回缓存成功，显示连接异常。

关闭/刷新客户端、界面进程崩溃、退出账号或切换门店会停止网关，不自动恢复授权或自启。普通页面切换不停止。停止会取消仍在授权验证或监听启动中的任务，防止停止后重新出现监听。多条 TCP 连接分别计数，单条连接关闭不误报全部断开。

验证：隔离数据库真实授权、实际 TCP/Thrift 房态查询、未支持的设备登录拒绝、启动/停止/重启、绑定篡改拒绝、端口冲突保留原监听、撤销停止通过。7 项已有协议/模拟器测试通过。真实 Electron UI 验证签发、启动、TCP房态读取、停止、重启、刷新和切店停止；类型检查和构建通过。未执行 NSIS 安装/升级或真实厂商面板业务验证。

状态仍为只读联调，尚未支持厂商设备登录/注册、菜单下发、上下钟写入和钟房播报协议。这是从“保存文件”推进到“客户端可运行现有只读协议”，不等于设备已自动接通营业。尚未发布云端或安装包。

## 2026-09-15 点钟王完整绑定自动识别（尚未发布）

重新核对用户提供的厂商 `Commlog` 后确认，`DeviceStatusAndRemoteControl` 记录内的 `sysRollBellKingDetailsList[].switchIp` 随房间分别为不同局域网地址，并与 `AnswerOneWaySuccess` 中实际回包目标面板地址一致；门店电脑地址为另一地址。因此 `switchIp` 的实际含义是房间面板 IP，不能解释成门店电脑 IP。

客户端现从本机 `HKLM\SOFTWARE\Eissoft\HARD\Cache` 的 `RollBellKingConfig` 中仅提取已获本机授权的 `rollBellKingId + roomName + switchIp`，形成“设备编号、房间号、面板 IP”完整绑定。门店监听网卡由全部面板 IP 唯一匹配的真实子网选择；多网卡无法唯一匹配时仍要求人工选择。`Get-NetTCPConnection -LocalPort 8032 -State Established` 只用于显示和交叉核对在线面板，不再用于猜测设备与房间关系。

冲突设备编号、畸形房间号、非私有 IPv4、未在本机授权列表内的设备、超大或无法解析的缓存均拒绝自动绑定。注册值、厂商账号、Session 和完整菜单正文不进入渲染进程。自动映射、冲突拒绝、子网选择和在线连接过滤已通过构造测试；类型检查和完整构建通过。尚未在门店电脑读取真实注册表并与实体面板逐台核对。

跨日日志验证进一步确认字段含义：2026-08-17 的 73,912 条可映射回包、2026-09-13 的 62,564 条可映射回包，其 `Answer device IP + RoomId` 均与配置中的 `switchIp + roomName` 一致，两天合计冲突 0 条；未映射记录不计为一致或冲突。2026-09-13 可用设备配置样本的 `type=2`、`deleteFlag=0`、`roomEnableStatus=0`、`online=true`。自动绑定现要求前三个状态字段精确符合当前 7 寸设备记录，防止删除、停用或其他类型的历史记录被重新启用；在线状态只作提示，不作为保存配置的必要条件。
