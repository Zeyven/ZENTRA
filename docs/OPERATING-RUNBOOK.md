# 澜序 SaaS 运维

只操作 `/opt/za-spa-saas`、新数据库 5433 和 `za-spa-saas*` 服务。不要替换旧应用的虚拟主机、安装器、环境文件或数据库。

## 开通与经营

平台管理员从 `/platform` 登录，开通商家并提供一次性老板邀请。商家老板激活后自行设置密码，创建门店、员工、房间和经营配置。商家入口使用商家编号、账号及密码；平台凭证不能进入商家桌面会话。正式库不预置示例业务。

管理员登录资料和加密恢复材料在本机 `.runtime` 私有目录中；此目录仅当前用户、SYSTEM 和 Administrators 可访问，Git 已排除。不得提交、发送到日志或混入安装包。

## 发布与回滚

先完成类型、构建、接口匹配、后端、浏览器及安装器验证，记录文件 SHA-256。`stage-release.py` 只上传构建文件和锁文件到新目录；不带环境文件。`activate-release.py` 切换新应用 symlink，验证失败恢复前一目录。数据库变更先运行独立备份，迁移账号只用于迁移，运行账号不能 DDL、TRUNCATE 或绕过 RLS。

Nginx reload 返回仅表示已通知主进程，HTTPS 检查应等待新工作进程接管并保持严格证书校验；持续失败撤回新虚拟主机。不得通过忽略证书错误完成发布。

## 备份与恢复

每日定时作业使用新 PostgreSQL 实例生成一致性备份并恢复到临时库比对。整体恢复不能直接覆盖业务运行中的正式库；先校验临时库、凭证和结构，再制定切换步骤。单商家恢复要求目标商家停用，先备份目标库，使用 `tenant-restore.py`，恢复后保留当前凭证并撤销旧会话。后台报表导出不是数据库恢复文件。

本机 `production-recovery.enc` 为加密恢复材料，配套 `production-recovery.key` 不存放在服务器。恢复验收已使用解密材料实际连接数据库并登录平台。定期将加密文件和解密钥匙分别纳入管理员控制的备份保管；不要把钥匙与公开安装包一起分发。

## 监测和容量

关注 `/opt/za-spa-saas/health/backup.json`、三个独立定时器和 API `/ready`。备份超过 26 小时或空间不足时监测失败；容量不足时迁移新应用，不提高配额挤占旧服务。当前只验收过报告中列出的 100 在线设备负载，持续观察真实商家数据增长。

支付、团购与设备仍处于未接入状态，必须取得新 SaaS 的独立授权并验证签名、设备协议和商家归属后再启用。
