# M5 — Tool Gateway / Approval / Vault

状态：进行中，未通过 Definition of Done。

- Approval 请求已有 user、task、run、action、resource、arguments hash、Task state version 与 expiry 绑定。新增数据库决策事务：只有目标活跃成员能在对应 Task/Run 的 `WAITING_APPROVAL` 版本上批准或拒绝；过期转为 `EXPIRED`，Task 状态变化转为 `REVOKED`。乐观版本检查拒绝重放，状态变化与审计/Outbox 原子提交。
- `GET /v1/approvals/:id` 可查看授权范围内请求，含绑定参数哈希。`POST /v1/approvals/:id/decision` 仅在注入式测试开关下使用；生产默认返回 `approval_decisions_unavailable`。真实 PostgreSQL 测试覆盖非目标用户、过期、旧版本、状态变化和重复决策；API 集成测试确认停用门控与失效请求响应。
- `ayra.consume_approval(...)` 在数据库锁住 Run → Task → Approval，重新核对运行者仍为 Workspace Owner、指定批准人仍为活跃成员、Task 正处于匹配 Run 的 `WAITING_APPROVAL` 版本，以及动作、资源、参数哈希和有效期；成功后原子转为 `CONSUMED` 并写入审计/Outbox。真实数据库测试验证错误绑定、撤销成员和重复消费均不能再次授权。
- 已建立 provider-neutral Tool Gateway：先由注入式 resolver 查询 canonical Run 身份/能力，再做注册表、schema 解析、Capability/资源授权、Risk/Policy 门控，以及写入幂等键、可逆 snapshot、高风险独立验证和精确 Approval binding。尝试审计成功后才消费 Approval；通过门控后才调用注入式 Vault adapter，输出必须经过 sanitizer，执行结果交由 Audit adapter。测试验证外部写入缺少授权或审计不可用时不会触及 Vault 或工具。
- Worker 包已有事务化 Approval consumer adapter，可调用数据库单次消费函数；它尚未接入正式 Worker 的 Tool Gateway/Workflow。真实 Vault/Policy/Audit adapter、生产工具和外部操作幂等恢复仍未实现。**批准尚不能授权任何工具执行**；生产门控保持关闭。
