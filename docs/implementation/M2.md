# M2 实施记录：Core Domain

状态：**PASS（工程 Definition of Done）**。M0/M1/M2 的阶段验收已通过；这仅表示 Core Domain 基础可进入 M3，不表示 AYRA 功能完整或可发布。

## 已实现

- PostgreSQL 表：Project、Task、Run、Conversation、Resource、Artifact、Approval、AuditEvent、OutboxEvent。每个租户实体显式保存 `workspace_id`，跨表组合外键验证同 Workspace 和同 Task/Run 关系。
- Task 与 Run 分表；Artifact 的 `task_id` 非空且存在数据库外键，Run 可选但必须属于同一 Task；Approval 绑定 user、task、run、action、resource、arguments hash、state version 与 expiry。
- 全部 M2 租户表启用并强制 RLS。Project 的写入限定 Workspace OWNER，MEMBER 可读；Project 版本触发器禁止跳号，租户和实体 ID 不可变。
- Project 创建和更新通过数据库触发器在同一事务写 Audit 与 Outbox。API 提供 `POST /v1/projects`、`GET /v1/projects`、`GET /v1/projects/{id}` 和 `PATCH /v1/projects/{id}`，使用已验证 AYRA 会话、Policy、RLS 和乐观并发版本。
- Project 创建要求 `Idempotency-Key`，同 Workspace、操作范围和键只保留一个结果；请求内容变更返回 409。幂等记录与 Project/Audit/Outbox 在同一事务提交。
- Task 草稿提供创建、列表、详情、版本化更新和软删除 API。创建要求 `Idempotency-Key`；创建后 `currentRunId` 为 `null`，不会隐式启动 Run。OWNER 可写，MEMBER 可读，Project 关联必须属于同一 Workspace。Task 创建、更新、软删除在同一事务写 Audit 与 Outbox。
- Project 提供版本化归档与恢复；普通列表和详情隐藏归档项，`archived=true` 可列出归档项。归档 Project 后不允许为其创建 Task；两种状态变更各产生审计和 Outbox 事件。
- Conversation 元数据提供幂等创建、列表、详情、版本化改名、归档与恢复。此阶段不伪称已实现消息存储或对话 Agent；四类写入事件与实体同事务提交。
- Resource 输入材料元数据提供幂等创建、列表、详情、版本化改名和软删除；sourceRef 在创建后不可通过普通更新改变。此阶段尚无文件上传、签名访问或内容解析。Resource 与输出 Artifact 保持独立。
- 关联 Project 的创建请求先确认幂等重放，再在新建路径锁定并验证 Project 仍活跃；已成功请求在 Project 后来归档时仍返回原实体，新请求被拒绝且不会留下未完成的幂等记录。
- Artifact 只通过受控内部 repository 创建与软删除，创建必须关联存在的 Task，且可选 Run 必须与同一 Task 匹配。创建要求幂等键；公开 API 只提供授权后的元数据读取，不暴露 objectRef 或开放 Artifact 创建。文件生成、签名下载与对象清理由后续模块实现。
- Task、Resource、Artifact 软删除现在同事务创建内部 retention handoff，状态为 `PENDING_POLICY`；在保留期限和执行器确定前不会调度或执行 purge。
- Artifact 的受控清理执行层已加入：只有外部明确设置政策、`READY` 与到期时间的请求才能被租约领取；Worker 对已管理的结果对象执行可重试删除后，数据库在单一事务内删除 Artifact 元数据、完成请求并记录审计/Outbox。无默认保留天数、无自动调度；Task/Resource、对象存储历史版本及未来 Search/Embedding 的最终清理仍未实现，因此完整 purge 生命周期尚未验收。
- Run 内部 repository 可幂等记录一次 `PENDING` 执行尝试并按 Workspace 授权读取；它不修改 Task canonical 状态、不派发 Temporal、也不对用户开放启动路由。Artifact 可选关联同 Task 的 Run，由组合外键保证。
- Approval 内部 repository 可幂等记录精确绑定 user、task、run、action、resource、arguments hash、state version 与 expiry 的 `PENDING` 请求；只有目标成员或 OWNER 可读取，普通 MEMBER 不可读他人的请求。决定路由保持关闭，批准与外部动作执行待 M5 安全边界完成。
- PostgreSQL Task 状态守卫只允许白皮书规定的阶段转换；暂停/阻塞保存原阶段，恢复只能回到该阶段，终态不可重新激活。普通 application_role 当前没有状态写权限，实际调度与控制路由留给 M3。

## M2 Definition of Done

- Domain invariants：组合外键、RLS、版本、Task 状态约束在 PostgreSQL 和签名会话 API 测试中均有覆盖。
- Task ≠ Run：创建 Run 后 Task 仍保持 DRAFT 且 `currentRunId=null`；Temporal 不反向成为 canonical state。
- Artifact 必须 Task-backed：`task_id NOT NULL` 与同 Workspace/Task 的组合外键拒绝孤儿或错配 Run。
- Outbox 与事务原子：Project、Task、Run、Conversation、Resource、Artifact、Approval 的创建/变更及回滚测试验证实体、审计、Outbox 一起提交或一起消失。
- 生命周期骨架：Project/Conversation 归档恢复，Task/Resource/Artifact 软删除，软删除同事务生成 `PENDING_POLICY` retention handoff；实际 purge 尚未执行。
