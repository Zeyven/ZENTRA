## 已实现

按 §3.3 建立五个应用与十三个共享包的 pnpm workspace。Web 使用 Next.js / React，桌面使用 Tauri 2 / React，移动端使用 Expo / React Native，API 使用 Fastify / OpenAPI，Worker 独立进程。当前客户端是明确标示的开发预览，不包含模拟账户、模拟任务或模拟授权。

建立共享严格 TypeScript 配置、ESLint、Prettier、Vitest、依赖锁文件和 GitHub Actions。Domain 的类型独立于供应商。静态工程检查限制 Domain 外部依赖，以及客户端引用敏感服务端包；它不替代后续的完整安全测试。

配置解析对缺失必要字段失败，数据库 URL 只接受 `application_role`，错误信息不回显凭据。环境初始化生成随机本地凭据、设置文件权限并保留已有环境文件。原有 `.env.local` 未读取到输出、未覆盖或加入 Git。

Compose 定义 PostgreSQL 18、Redis、Temporal dev 与 S3-compatible MinIO。API `/health/live` 只表示进程存活；`/health/ready` 返回 503。Worker 不接受任务。无任何用户仓库或模型驱动 shell 在宿主 API 中执行。

## 本机一条命令验收

2026-09-24 在 Docker Desktop 上补齐原版同摘要镜像。PostgreSQL 18.6、Redis 8.2.1、Temporal 1.9.1 从 Google 官方 Docker Hub 缓存下载，并将镜像清单摘要分别与 Docker Hub 原仓库核对一致；MinIO 服务和初始化工具从 Compose 指定的 Quay 镜像下载。首次运行发现 `init-postgres.sh` 缺少可执行权限，修正文件模式为 `100755` 后，在本轮新建的空数据卷上重新初始化。

`pnpm infra:up && pnpm infra:verify` 通过：PostgreSQL 18、非超级用户且无 `BYPASSRLS` 的 `application_role` 及其登录、Redis PONG、Temporal 集群与 `ayra-development` 命名空间、S3 写入/读取/删除均经运行中的容器实测。根目录 `pnpm dev` 随后一次完成环境初始化、基础设施启动与验证，并同时启动 Web、API、Worker；Web `GET /` 为 200，API `/health/live` 为 200。API `/health/ready` 按尚无业务能力的骨架设计返回 503。测试使用 `API_PORT=4100` 避开已有的本地 API 进程，Web 使用默认 3000 端口。最后完整 `pnpm check` 退出码为 0，确定性测试为 6 文件 / 19 测试。

后续 UI 根据用户提供的 AYRA0–AYRA3 图片调整，Logo 使用用户图标包中的 charcoal 导航版及 porcelain 应用版。参考中的业务内容以真实空状态呈现。Chat/Work 已加入明确标示的设备本地草稿恢复与导出；它不是服务端 canonical 项目、任务或成果，不调用模型、不创建业务任务。官网与桌面分离后的视觉检查细节见根目录 `design-qa.md`；本轮 UI 范围见 `docs/implementation/UI.md`。
