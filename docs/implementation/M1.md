# M1 实施记录：Identity / Workspace / Policy

状态：**PASS（M1 工程 Definition of Done）**。M0 已通过；M1 的数据库、身份适配器、Policy 与 API 垂直切片均有运行证据。真实 Clerk 项目与桌面登录属于发布前联调，尚未验证。

## 已实现

- `users`、`external_identities`、`workspaces`、`workspace_memberships` 与迁移校验和表。供应商 subject 只存外部身份映射；账户 API 返回 AYRA UUID，不依 email 自动合并。
- `application_role` 下强制 RLS；成员身份是 Workspace 授权来源。安全定义者函数原子创建 Workspace 和 OWNER 成员关系，普通应用角色不能直接改外部身份映射。
- IdentityProvider 接口与 Clerk JWT 验证适配器；缺少配置时受保护 API 返回 503。PolicyEngine 检查 Workspace 成员角色，数据库 RLS 是第二层防线。
- `/v1/account`、`GET/POST /v1/workspaces` 和 `GET /v1/workspaces/{id}`。服务端验证 Bearer 会话后，在单个 PostgreSQL 事务中解析 AYRA 用户并设置事务局部 RLS 上下文。未知或越权 Workspace 统一返回 404。
- `pnpm migrate` 按文件名排序、记录 SHA-256 并拒绝已应用迁移变化；`pnpm dev` 在启动 API 前运行迁移。
- AYRA 自有会话表只保存供应商 session ID 的 SHA-256，API 返回 AYRA UUID。会话列表、撤销单个会话和撤销其他会话均受本人账户限制；撤销后旧会话即使仍携带已签名 JWT，也不能访问 AYRA API。

## 验证证据

- 本机 PostgreSQL 18 上迁移首次应用和重复运行均成功；第二次报告 `Already applied`。
- `pnpm test:integration` 使用真正的 `application_role` 登录，验证本人 Workspace 可读、跨 Workspace 读写拒绝、成员可读不可改、暂停成员后访问撤销。
- `pnpm test:api` 使用本地签名 JWT、真实 Clerk 验证适配器与 PostgreSQL，验证未登录/无效会话拒绝、账户和 Workspace 创建、跨租户 404、列表隔离、供应商 subject 不出现在响应。同一个连接池连接依次服务两个用户，验证事务局部上下文没有串户。
- 同一测试还验证第二个会话、撤销其他会话、撤销当前会话、跨账户撤销拒绝，以及撤销后 API 401。

- `pnpm check` 已通过，涵盖 lint、格式、类型、21 项确定性测试和所有应用构建。[M1 最新 CI](https://github.com/Zeyven/ZENTRA/actions/runs/35907080354) 已通过工程、数据库/API 集成与 macOS/Windows 原生构建。
