# 平台超级管理员与单商家备份恢复

## 使用方式

平台登录后，在“商家管理 → 商家目录”直接点击“超级管理”进入目标商家，或点击“备份恢复”。所有有效的平台账号均有超级管理权限，无需商家老板授权，不受一小时支持授权期限、门店角色或商家停用状态限制。未激活商家也可先配置门店，之后仍由真实老板激活账号。

进入后可以使用系统已提供的经营、资金调整、退款、删除、状态恢复操作，并在“商家管理 → 员工与门店授权 → 维护账号”修改、停用、启用或重置老板及员工账号。超级管理不受门店的经营审批阈值限制，直接操作会记录审计；金额、数据归属、幂等和账本完整性校验继续执行。

平台操作使用独立的内部业务身份，不能登录商家端，不冒充老板，不出现在员工列表。实际平台操作人同时记录到商家审计与平台审计，随业务事务一起提交。平台退出、改密、会话撤销或账号停用后，超级管理会话失效；正常平台登录有效期仍是 8 小时。

原有“支持授权”保留为历史兼容入口，旧只读/配置/完整维护会话仍执行原授权范围和期限，不自动扩大权限。需要超级管理时直接从商家目录进入。

“备份恢复”的步骤：选择备份、填写原因、验证并预览、填写商家编号及当前平台密码、确认恢复。预检有效期 30 分钟，实际执行重新检查平台账号、会话及凭据版本，不依赖老板是否启用或存在支持授权。旧授权模式下已排队的任务仍按原规则验证。

## 恢复范围与结果

- 恢复对象是仍存在的指定商家；不支持凭旧备份重新创建已彻底删除的商家或账号。
- 按备份时间点整体替换该商家的业务数据，并非只合并一条删除记录。备份之后的业务变更会被替换，执行前自动创建回滚备份。
- 备份中存在的已删除业务记录可以恢复；永久删除的门店只能通过此受控备份恢复流程恢复，普通门店恢复按钮仍然拒绝。
- 保留当前账号密码和账号状态；当前员工门店权限仅在恢复后仍有对应档案时保留。
- 设备网关授权、设备绑定、历史会话和运行缓存不从旧备份复用，需重新配置设备授权。
- 恢复后暂停该商家营业、撤销商家会话和支持授权；平台超级管理员可继续核对并重新启用商家。任务结果可由原提交平台人员继续查看。平台中央审计不会随业务快照回退，也不会重复导入历史平台审计。
- 没有包含所需记录的备份就无法恢复；历史账号缺失、身份不匹配、未知结构版本、完整性校验失败会拒绝执行。

## 执行保障

运行 API 只提交任务，不获得系统管理员或直接恢复数据库权限。独立 root worker 只接受固定数据库、受管理且有 SHA-256 清单的本机备份。先在临时数据库恢复验证，必要时仅对临时库执行已部署的可信迁移。

恢复锁覆盖暂停营业、回滚备份和事务替换阶段，阻塞该商家的运行时写入（包括支付回调）；其他商家不受该锁影响。业务替换与任务成功状态在同一事务提交，失败整体回滚。worker 中断不会自动重试破坏性操作。暂停后发生失败时仍保持暂停，需核对任务结果再启用。

2026-09-18 随 V1.0.20 发布生产：生产备份已在临时库恢复并比对 86 张表，迁移 037 至 041 已应用，API/Web 已切换，恢复 worker 与定时器已安装并正常执行。备份目录同步通过，未执行生产商家的删除或恢复验收。后续部署仍应先备份、迁移、部署 API/Web，再运行 `scripts/install-recovery-service.py`；发布需有用户授权。

应用回滚前应停用 recovery timer，等待正在执行的任务结束；不要对正在恢复的库强行逆向迁移或覆盖。保留新增表及审计记录。数据回滚同样走已验证的目标商家备份恢复流程。
