# V1.0.6 门店角色与操作权限

权限同时检查商家归属、门店授权、角色上限、页面、日常操作及资金操作。老板可以逐店给同角色员工分配不同权限；角色名称本身不代表无限访问。

| 角色 | 默认工作范围 | 可单独授权的敏感操作 | 保留限制 |
|---|---|---|---|
| 商家老板 | 本商家全部门店与经营配置 | 全部本商家经营权限 | 无平台或其他商家权限 |
| 店长 | 本店运营、会员、钟房、库存、报表、设置、审批 | 结账、折扣、退款、赠送、取消、充值、资产/库存调整、反结账、导出、审批 | 不能管理员工账号/授权；不能修改审批阈值；不能审核自己申请 |
| 收银 | 房态开房、订单、会员接待、预约、叫号、交班、本人审批申请 | 默认结账、充值；折扣、退款、赠送、取消需老板单独勾选 | 不开放反结账/充值冲销、资产调整、审批决定、人员配置、经营设置 |
| 技师 | 已关联档案的本人工单、报钟、考勤与本人服务记录 | 无资金权限 | 不能操作他人钟单、收银、会员资产或其他门店 |
| 平台支持 | 老板临时授权范围内的查看或配置维护 | 不执行经营资金操作 | 只读支持不允许配置写入；按支持期限/撤销校验 |

## 16 项日常操作

开房；加项目/换房/挂单并单；按项目价格加钟；落钟/结束服务；派钟/换技师；报钟/暂停恢复/考勤；打扫/房态维护；会员资料维护；预约登记变更；取号叫号取消；开班交班；门店经营配置；房间/项目/会员方案配置；采购库存调拨；技师档案技能配置；公告维护。

这些操作可单独关闭。关闭后保留已授权页面的查询能力；资金权限另行检查。例如看见订单不代表可以加钟或退款，看见门店设置不代表可以保存。页面未授权时，勾选操作也不能绕过页面限制。非本角色支持的选项及缺少对应页面的选项显示灰色并说明原因。

既有日常权限通过 operations=NULL 继承原角色行为，并继续受原页面限制；operations=[] 明确表示关闭全部日常操作。旧客户端保存时遗漏 operations 不会清掉已有日常限制。新客户端“采用门店角色权限”可明确恢复继承。原有资金权限和个人页面白名单不批量覆盖。

## 审查修复

- 统一服务端、角色配置及员工编辑器的资金权限上限，取消收银“可勾选却被接口拒绝”的反结账、资产调整、审批决定选项。
- 16 项操作在服务端请求执行及幂等结果重放前校验；主要操作按钮同步禁用，设置支持只读状态。
- 退押金补上 refund 权限，不能仅凭账单访问权执行。
- 会员折扣和等级变更同时要求管理角色及 discount 权限，保存联系方式不把自动升级等级写成永久人工等级；收银不显示管理专属的会员分析/分群入口。
- 报表 CSV 导出按钮及执行函数校验 export；设置内审批按钮校验 approve 并禁用本人申请的审核。
- 巡房登记使用 roomStatus 权限，工资锁定使用 settingsManage 权限；只读人员不能通过这两个写入入口绕过操作限制。
- 审批阈值仅老板维护，店长不能降低自己的审批门槛；公告维护允许获授权店长。
- 库存调拨源店、目标店同时验证 inventoryManage，不靠当前选店权限代替目标店授权。
- 员工授权修改沿用 access.changed 事件，接口重新查询授权、实时连接重新验证；角色切换不保留超出新角色范围的授权。

## 兼容与发布
