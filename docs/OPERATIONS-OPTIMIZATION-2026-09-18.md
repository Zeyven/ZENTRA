# 澜序营业流程优化验收

范围：落实竞品调研提出的房态、排钟、岗位权限、设备配置和日常对账五组软件优化。保留原有功能，不改变业务结算算法，不接入此前排除的外部支付、团购、打印机或钱箱。

## 1. 房态与营业操作
- 房间卡片显示服务项目、时长、待接单、待上钟、暂停、剩余时间、到时和待结账。
- 使用服务端保存的暂停累计时间推导结束时间；暂停或尚未接单不会误报超时。
- 退单项目不再出现在服务提醒中。未知状态显示待确认，不回退成空闲或正常服务。
- 待处理按钮展示真实房间数量，点击筛选，并可恢复完整列表；原房间开单和收银侧栏保留。
- 显示最近同步时间；刷新失败保留上次数据并明确标识。
- 技师栏补充当前服务房间。待接单与服务暂停不再统一显示为上钟中。

## 2. 钟房排钟
- 休息技师不进入可排钟队列。
- 队列排序与已有自动派钟的服务单数口径一致，同时展示已开钟服务单数与已完成钟数。
- 同钟数排序由具备技师管理权限的人员调整；新界面要求填写调整原因。
- 审计保存调整前后顺序、操作人、时间与原因，并提供本店最近30次查询。
- 旧客户端未提交原因时保留兼容，明确记为旧客户端未填写，不能伪造原因。
- 自动分配审计补充选择方式、规则、当时单数与顺序；派钟算法本身未更改。
- 播报与派工明确区分，播报前复核页面当前技师状态。

## 3. 岗位权限
- 保留已有岗位默认值、员工逐项授权、门店作用域和服务端权限上限。
- 修复钟房入口仅按角色显示的问题，改为检查对应细分操作权限。
- 店长与收银的日常操作、只读店长、即时撤销及接口拒绝由回归测试验证。
- 首页经营提醒也按页面权限过滤，不能通过提醒读取未授权库存、账单、设备或交班信息。
- 网关授权签发仍仅限老板，没有扩大平台支持或员工权限。

## 4. 设备配置流程
- 增加检测识别、点钟王绑定连接、刷牌输入测试、报钟器配置试播四个定位步骤。
- 现有检测、绑定、心跳、授权和协议状态仍分开显示，不把网络连通当作业务成功。
- 手工配置发生多端版本冲突后重新读取，拒绝覆盖另一终端的新值。
- 保存前复核权限；门店业态选择补齐同步锁与异常反馈，保留简称。
- 修正串口草稿说明，避免声称刷牌器专用串口已经配置或驱动已完成。

## 5. 经营提醒与对账
- 房态首页集中显示授权范围内的库存、长时间未结账、审批、反结账、网关授权/心跳和近期现金差异。
- 最近7天现金差异标记为历史核对记录，不伪称尚未处理的故障。
- 报表新增原始记账流水，按日期和门店过滤，游标分页；包含流水、订单、班次、操作人、原因和冲回原流水编号。
- 明确销售、优惠、收款、充值和押金不能全表直接相加为营业额。
- 交班填写实点现金，差异要求说明；服务器在锁定班次后重新核对班次ID与应交金额。
- 盘点结果保存至现有不可变班次快照，无数据库结构迁移。旧客户端未盘点的记录显示未盘点，不能视为零差异。
- 响应丢失后保留原金额和请求编号，重试核对原交班；浏览器测试通过真实落库后丢弃响应验证。

## 验证记录
详细结果见本地 `.runtime/operations-ux-*` 日志。测试数据全部位于隔离的 `za_spa_saas_test` 数据库。

最终结果：核心回归50项、设备与安全回归16项、网关回归30项全部通过，无失败或跳过；浏览器与Electron共6个独立用例通过（两份运行日志包含1个重复用例）。最终源码的类型检查、服务端/共享接口/Electron构建和Web构建均成功。未知服务状态的最后补充修正也通过针对性测试。

- 核心业务回归：`operations-ux-core-final.log`。
- 设备、安全、检测回归：`operations-ux-device-regression.log`。
- 网关协议及生命周期：`operations-ux-gateway.log`。
- 浏览器权限、收银弹窗、弱网交班：`operations-ux-browser-verified.log`。
- 最终钟房、营业流程与Electron配置冲突：`operations-ux-ui-final.log`。
- 类型检查及两端构建：`operations-ux-typecheck-final.log`、`operations-ux-build-final.log`、`operations-ux-web-build-final.log`。

## 发布与外部边界
- 此次不修改生产数据库，无新增SQL迁移；云端与已安装客户端未由本轮发布更新。
- Electron测试使用实际编译资源和本地隔离API代理，不等于安装器或自动升级安装验证。
- 实体点钟王、刷牌器和报钟器的协议授权、驱动及门店现场业务验收仍不能由电脑模拟或网页测试替代。本轮没有声称这些外部条件已解决。
