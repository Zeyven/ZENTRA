# 会员权益与充值退款验收

2026-09-08。仅针对独立 SaaS 测试数据库 `za_spa_saas_test`；不是正式上线或完整会员模块验收。

## 本轮实现

- 会员详情提供本金、赠金、次数、积分流水及原充值批次分配。每页 50 条，使用游标翻页；首次打开复用详情响应，减少重复读取。
- 权益调整显示四类权益的当前值、调整值和结果，原因必填。失败保留输入；重新读取当前权益后才能以新版本提交。
- 充值退款展示原充值门店、实收金额及收款方式，明确是线下退款登记，不声称自动向支付渠道退款。只有原批次权益可全部冲回时才能成功；保留原流水和冲回关联。
- 达到退款审批阈值时先提交审批，余额不变。另一名管理员批准后，原申请人在审批中心执行。审批期间权益发生任何变动，即使余额恢复原值，也拒绝旧审批。
- 调整和退款成功响应直接返回已提交的账户及流水；充值成功直接使用返回账户更新列表。现有实时刷新合并机制继续负责列表更新，提交按钮不再等待第二次列表查询释放。
- 充值、调整和退款防止快速重复点击；提交丢响应时锁定表单和关闭操作，使用相同幂等键核对原请求。当前保障覆盖同一页面会话；重启浏览器后的未确认操作恢复仍待统一验收。
- 会员消费画像修正为实际 API 返回的商品名称和数量字段，移除详情内重复的旧权益表格。

## 数据与权限

- `016-member-asset-version.sql` 增加会员 `asset_version`，所有钱包变更在同一事务内递增。只迁移隔离测试库，生产库仍未初始化。迁移为增加带默认值的列；无旧业务数据库操作。
- 服务端锁定账户后校验权益调整版本。不同请求编号同时提交同一版本只允许一次成功；同一成功请求的重放仍返回原结果。
- 已归档会员禁止调整权益；冻结会员可以登记原充值退款，无需重新开放消费。
- 商家通用会员的员工流水限定当前门店；老板可查看本商家该会员的各店流水。分配明细只返回该笔交易使用的批次，不返回其他批次可用余额。
- 退款同时校验当前门店和原充值门店的管理授权、会员页面及退款动作权限。原请求重放之前再次校验原店权限，撤权不能通过缓存响应绕过。
- 客户端拒绝用旧成功响应覆盖已读取的较新权益版本。数据库仍使用原有精确金额、FIFO 批次和原子记账机制。
