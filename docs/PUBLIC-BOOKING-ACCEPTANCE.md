# 顾客预约与候补

顾客入口为 `/customer/{商家编号}/{店号}/booking`，只返回该店公开项目、技师显示资料和可营业状态。商家预约页可复制对应入口，门店端可查看候补队列。接口不提供跨商家的门店目录。

预约时间须带时区，未来 180 天内；按服务时长、人数、房间及指定技师检验时段冲突。门店级调度锁协调顾客预约和前台预约，取消、改期、候补确认均检查版本。未来预约占用预约时段，不直接把空闲实体房间改成正在营业。顾客凭随机 Bearer 查询与操作自己的预约，数据库保存哈希，不向门店列表返回顾客凭据。

候补按创建顺序匹配，确认期限最长 15 分钟；过期释放预约时段。顾客在原页面查看名额并确认，没有模拟短信发送。后台扫描仅处理活跃商家与门店。预约需要非零线上订金时明确返回 `PAYMENT_NOT_CONNECTED`，没有支付单、扣款或虚构回调；支付按用户确认只预留接口。

测试库已应用 020、021：新增报价快照和候补版本，补上 offered/awaiting_payment 状态约束。首轮取消触发候补失败，数据库原约束仅允许前台状态；021 明确扩展合法状态后用例通过，没有移除状态约束。

顾客预约与既有预约/排队合并回归 8/8 通过，包含最后一个房间并发只成功一个、同请求重复提交、跨商家资源/凭据拒绝、改期版本、取消后候补、确认超时。新增门店候补权限及后台编译运行合并补验 6/6 通过。

浏览器用例首次因 select 标签定位未匹配而超时；页面快照确认 combobox 名称及项目正确，改为按 combobox 角色定位后 1/1 通过。实际模拟响应丢失后刷新页面，sessionStorage 保存的原请求可恢复，数据库只产生一条预约，再取消成功。改期、确认、取消使用已提交返回值更新页面，不等待额外详情查询。

正式 Web 部署、全套 Windows/经营回归、候补时间范围和顾客优惠券等其余完整验收仍继续进行。
