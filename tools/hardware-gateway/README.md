# 房间面板网关：离线验证阶段

## 本机虚拟点钟王

运行 `node tools/hardware-gateway/simulator.mjs`，打开 `http://127.0.0.1:18033/`。终端内按 Ctrl+C 停止服务；关闭网页不会停止服务。

此页面通过真实的本机 TCP/Thrift 请求访问独立测试网关，使用明确标注的合成房间 SIM203。无需门店账号，不访问云端，不产生营业订单或扣款。它用于检查当前协议的明确拒绝结果、未绑定设备与查询失败场景；不会模拟成功房态。

设备登录、技师登录、上钟、加钟、下钟按钮用于检查当前协议的拒绝响应，尚不支持完成这些业务。该模拟器不是厂商固件模拟，不证明真实面板注册、菜单、写操作或播报兼容。

验证命令：`node --test tools/hardware-gateway/gateway.test.mjs tools/hardware-gateway/simulator.test.mjs`。本轮 7 项通过，包含独立 Apache Thrift 样本、拆包合包、真实 HTTP 到 TCP 往返、错误分支与跨来源请求拒绝。

此目录是独立的Node.js24测试网关，不是已完成的生产设备驱动。它接收并校验已观察到的TCP/Thrift请求。用户提供的当前固件日志已证明`SystemClockInfo`的响应字段，因此网关可以只读返回房态及不含顾客、支付信息的钟列表；真实面板是否接受本网关仍须现场验收。不会读取厂商云端或使用厂商Session。

`vendor-login.mjs`、`vendor-menu.mjs` 和 `vendor-runtime.mjs` 是当前点钟王登录准备层：分别实现已证实的本地签名、租户菜单筛选和 Windows 原厂缓存只读装载。运行时只接受本机已经存在的厂商授权记录，不请求厂商授权服务；秘密仅保留在 Electron 主进程内。缓存、绑定和当前澜序授权均完整时，桌面网关可构造受限的`SystemDeviceLogin`应答；该应答只经过合成 TCP 测试，尚未确认真实面板接受。它们不开放任何业务写入，取得缓存不等于实机验收完成。

当前实现：

- 从用户提供的程序静态重建TRpcRequest/TRpcResponse的字段编号、类型和OnAskCall/OnAnsweCall方法。
- Thrift binary非分帧传输，支持TCP拆包/合包、消息长度限制、连接上限、闲置断开和慢接收端保护。
- 设备IP、设备编号、房间编号与澜序房间ID显式绑定；每个进程只有一个门店的独立网关授权。授权撤销后云端查询失败，不返回缓存的成功状态。
- 日志不输出认证头、设备Session或业务正文。
- 设备未绑定、操作未开放及云端查询失败时，外层TRpcResponse.exstatus为1，exmsg携带提示；业务JSON含msg/data，不再错误地发送外层成功。非法结果及超过256KiB的应答拒绝发送。

尚未完成：实机确认设备登录注册与菜单下发的真实兼容性、技师身份验证、报钟/下钟等写操作、钟房Android机顶盒应用及播报协议、自动安装与长期运行服务。除受限的缓存驱动`SystemDeviceLogin`测试应答及只读`SystemClockInfo`外，这些请求目前明确失败，不能用本工具替换营业中的厂商程序。

## 现场单台验证准备

1. 选择空闲或备用面板，并记录原服务器、端口和房间号以便恢复；保留厂商原8032端口服务。
2. 测试环境中由老板在“门店设置 → 设备接口 → 门店硬件网关”绑定房间、设备IP与设备编号，签发七天只读授权并下载私有配对文件。密钥仅本次可下载，列表不返回密钥，数据库仅保存摘要。员工会话与厂商Session均不能替代此授权。
3. 下载文件默认监听127.0.0.1、端口18032。现场单台测试时填写门店电脑真实网卡IP，确认房间绑定。文件含密钥，请仅保存在门店电脑私有目录，不提交代码或转发。也可用环境变量`ZA_THERA_GATEWAY_TOKEN`覆盖文件令牌。
4. 运行`node tools/hardware-gateway/bridge.mjs 私有配置路径`。启动前会验证澜序门店授权和只读接口。端口占用时退出，不结束厂商进程。
5. 现场人员协助采集单台面板连接、登录和心跳的抓包，确认设备显示及错误后，再决定下一步业务写入适配。

网关仅应部署在可信门店局域网；设备IP/编号不是密码学身份认证。不要将测试监听端口暴露公网。现场还需确认面板是否支持独立服务方，登录所需`regsn`含义未知，不复用或伪造厂商注册信息。

协议参考：https://github.com/apache/thrift/blob/master/doc/specs/thrift-binary-protocol.md

## 失败分支修正验证

`node --test tools/hardware-gateway/gateway.test.mjs` 当前5项通过，包括3种真实TCP失败路径、独立Apache Python Thrift 0.22.0生成的失败帧逐字节比较、非法/超长应答拒绝和已有拆包/合包及绑定回归。`failure-fixtures.json`是独立库生成的合成期望值，不是厂商设备抓包。

菜单静态分析确认：厂商发送前会将日志中的MenuArray占位符替换为数组。当前没有完整菜单定义及第三方设备注册合同，故仍拒绝SystemDeviceLogin，不生成占位菜单或伪造注册成功。具体指令证据见`docs/HARDWARE-EVIDENCE-2026-09-14.md`。

本次仅修改独立网关协议模块及测试，没有部署云端、安装包或门店设备；实机互通仍未验证。
